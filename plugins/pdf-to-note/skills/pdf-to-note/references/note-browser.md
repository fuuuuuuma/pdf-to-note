# noteの配置・保存・公開

UI名・エディタ仕様は変わるため、毎回現在の画面とドキュメントから操作対象を確認する。記事ID、DOMのUUID、textboxの順番を固定しない。

## ブラウザの準備

本Skillの継続指定は **Codexアプリ内の内蔵ブラウザ（@ブラウザ／@Browser、ID `iab`）**。ブラウザ作業はここで行い、ユーザーに見えるタブを使う。既存タブを使う場合も現在のドキュメントに沿って `iab` のタブを選ぶ。ログイン済みChrome、Safari、Edgeや外部Playwrightへ自動で切り替えない。今回のユーザーが別ブラウザを明示指定した場合だけ、その指定を優先する。

利用可能なブラウザSkill／CUAドキュメントを読む。現在のCUAで新規タブを開く入口は次の形式。最初の呼び出しではこのAPIだけを実行し、返されたドキュメント・UI状態を読んでから続ける。仕様が変わっている場合は現在のドキュメントを優先する。

```javascript
let tab = await cua.createBrowserTab("iab", "https://note.com", { visible: true });
```

CUA再開時はドキュメントを再取得し、対応APIだけを使う。内蔵ブラウザを操作するためのツール内Playwright APIは使えるが、外部ブラウザを起動するPlaywright実行環境へ移行しない。DOM評価は読み取り・状態確認に使い、エディタ内部の状態変更や非公開APIの呼び出しに使わない。

内蔵ブラウザ上のログイン状態とアカウントを、プロフィール・編集画面で確認する。Chrome等でのログイン状態を前提にしない。新しい制作依頼では新規記事を作成し、その実行IDと作成した編集URLを対応づける。画面に以前の下書きが開いていても、今回の対象として再利用・上書き・公開しない。既存記事の再利用はユーザーが続行・再利用を明示した場合だけ行い、指定された編集URL等から対象を確認する。ログイン・認証が必要でエージェントが進められない場合は、下書きと素材を保存し、Codex内蔵ブラウザの該当タブで必要なユーザー操作を案内する。内蔵ブラウザの操作が利用不能な場合も、別ブラウザへ無断移行せず、保存済みの成果と不足している操作を伝える。

## タイトル・本文・見出し画像

画面で確認したタイトル入力と本文編集欄を使う。HTML形式の貼り付けが対応していれば、ブラウザのクリップボード／paste APIと通常UIで反映する。Markdownをそのまま貼って見出し・太字が完成したと思い込まない。少量で書式を確認してから全文を入れ、保存する。

見出し画像は「画像を追加」→「画像をアップロード」からファイルを選ぶ。ファイル選択の待機をクリック前に開始する。クロップのプレビューを確認し、文字切れを直して保存する。元サイズが正しくても、サイト側の表示を別に確認する。

## 本文画像の挿入

1. 配置台帳の正確な文章アンカーまたは見出しを、保存後の本文から見つける。
2. 通常UIでカーソルを段落末尾に置く。Endキーは折り返し行の末尾になることがある。必要なら読み取りで現在の選択位置を確認し、目的の段落末尾まで移動する。
3. 新しい空段落を作る。最初のEnterが段落内改行になり、次のEnterで空段落になる場合がある。Enterの回数を固定せず、実際の空段落を確認する。
4. 左側の「メニューを開く」を開き、「画像」が表示されるまで待つ。直後の古いスナップショットを根拠に誤操作しない。
5. ファイル選択イベントの待機を開始してから「画像」をクリックし、実際の絶対パスを指定する。
6. アップロード後、画像がHTTPS URLとなり、画像要素のcompleteとnaturalWidthが有効か確認する。data URL・一時プレビューだけでは完了にしない。巨大なbase64をツール出力に出さない。
7. 余分な空段落があれば、位置を確認して通常の編集操作で除去する。Backspaceを盲目的に繰り返さない。本文と見出しが残っていることを確認する。

ファイル選択APIが失敗した場合のみ、利用中ツールの対応範囲でCodex内蔵ブラウザが開いたOSのファイル選択画面を操作する。「フォルダへ移動」画面の表示を確認してからパスを入れる。古いクリップボードや表示前の入力で別ファイルをアップロードしない。ファイル選択のためにChrome等へ切り替えない。

## 保存後の照合

下書きを保存し、現在のDOMから本文領域だけのHTMLを取得する。ページ全体のナビゲーションやおすすめ記事を混ぜない。本文テキスト・見出しの列・本文画像数・各画像の読み込み・前後の文章・見出し画像を確認する。

`verify_note.py` は原稿HTMLと保存HTMLの空白差を除いた本文、見出しの段階と文字列、画像タグ数を照合する。figcaptionは本文照合から除外するので、キャプションは別に確認する。スクリプトが合格しても、元PDFの網羅、画像の読み込み・意味・配置、記事の公開は証明しない。

読める大きさの本文画像、画像と該当説明の位置関係、見出し画像をスクリーンショットで確認する。画像挿入後も本文の要点が減っていないか論点対応表を確認する。

## 無料公開と完了確認

本Skillの今後の記事制作にはnote公開までのユーザー承認がある。最新指定に「下書きのみ」「公開前に確認」がなければ、品質確認後に公開画面へ進む。無料記事として設定し、公開範囲・有料設定が意図どおりか確認して公開する。新しい確認指示がある場合は、完成物を揃えたここで確認する。

公開操作の結果が曖昧なときは、記事一覧、編集対象、公開URLを確認する。新しい記事を作ってやり直さない。既に公開されていればその結果を検証する。操作拒否やエラーがあれば理由と保存状態を記録し、未公開を公開済みと報告しない。

実際の公開ページを開いて次を確認する：

- 正しいアカウント・タイトル・URL。
- 無料で本文を最後まで読めること。可能ならログアウト状態の表示でも確認する。
- 本文・見出しが原稿どおりで、図版が該当説明の近くにあること。
- 見出し画像と本文画像が読み込まれ、スマートフォン相当の幅でも読めること。

`publication-receipt.json` の例（値は実測で埋める）：

```json
{
  "status": "published",
  "title": "実際のタイトル",
  "public_url": "実際に開いて確認したURL",
  "editor_url": "対象記事の編集URL",
  "published_at": "確認できた公開日時",
  "verified_at": "確認日時",
  "free": true,
  "body_checked": true,
  "inline_images_expected": 3,
  "inline_images_loaded": 3,
  "cover_checked": true,
  "proof_paths": ["実際のスクリーンショット絶対パス"]
}
```

不明な公開時刻はnullとし、操作時刻／確認時刻を別に残す。下書きの場合はstatusをdraft、public_urlをnullにし、未公開として記録する。例の値を使わず、今回の実測値を記録する。過去案件の検証結果で今回の公開確認を代用しない。

対応するブラウザAPIがある場合は、完成した公開ページまたは完了した下書きをdeliverableとして残す。handoffはユーザー操作や承認が本当に必要な場合に使う。最終回答でURLと確認画像を示し、公開・保存・未完了を区別する。
